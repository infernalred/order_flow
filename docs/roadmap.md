# Roadmap OrderFlow

Roadmap оформлен как Markdown task list:

- `- [ ]` — задача ещё не выполнена;
- `- [x]` — задача выполнена и проверена.

Галочка ставится только после реализации и проверки результата. Чекбокс всего этапа отмечается после выполнения его Definition of Done. При работе над проектом этот файл нужно обновлять в том же commit, что и соответствующий код.

## Как проходить план

План рассчитан на разработчика, знакомого с C#. Знание ASP.NET, SQL и распределённых систем не предполагается: необходимые понятия разбираются перед практикой. Нумерация существующих этапов сохранена, чтобы не потерять прогресс.

Порядок: **A → B → 0 → 1 → C → 2 → 3 → 3B → 4 → 5 → 6 → 7 → 8 → 9 → 10**. Базовые context и ожидание goroutine изучаются в B до shutdown; подробная concurrency — в C до Inventory. Этапы 7–10 — продвинутый трек; работающий монолит является самостоятельным учебным результатом.

Каждый блок проходит цикл: объяснение с сопоставлением C# → маленькое упражнение → реализация в OrderFlow → тест → самостоятельное изменение и разбор. Галочки реализации не доказывают освоение темы. Для завершения этапа нужны и технический DoD, и учебная проверка без пошаговой подсказки. Уже выполненный код не переписывается ради упражнения: знания проверяются отдельной небольшой задачей.
